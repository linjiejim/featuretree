## 为什么

2026-11-07 用 Claude Code 通过 Arbor 建一支钢笔，暴露出下面这些问题：

| 发生了什么 | 原因 | 这里的对策 |
| --- | --- | --- |
| 把「钢笔」建成了按动圆珠笔，建完才发现 | 没先复述要建的是什么 | 提示词：开建前用一两句话说出物体、零件清单、做到什么程度 |
| 笔尖做坏了，agent 却说「整支笔的图太小，细节请到窗口里放大看」 | `look` 固定 448×336，总是框住整件；147 mm 的笔，笔尖只占几个像素 | `look` 加 `focus`、`section`、`dir`、`size`；最后一步改动很小时自动加一张特写；结果里写比例尺 |
| 笔尖和笔舌之间空了 0.5 mm，笔尖悬着 | 没有量；也没有「这两块应该贴上」的核对 | `measure` 能量两个特征或零件之间的距离；核对表加 `gap`（`max: 0` 就是必须贴上） |
| 修形时沿 Y 切穿，在半圆壳的两侧擦出很宽的斜面 | 只能「大矩形减去轮廓」再整体切；没有求交，也不能只切笔尖 | 求交（`mode: "intersect"`）；笔尖单独做成一个零件，修形只作用在它上面 |
| 为了让弧壳朝 -Y，只能把截面画到 -X 侧去凑 | `revolve` 没有起始角 | `revolve.start`、`revolve.symmetric` |
| 刻在笔帽上的字，中间深 0.9，两边只有约 0.5 | 文字只能沿草图法向投影着切 | `extrude.onto`：沿选中的面（平面、圆柱面）的法向等深 |
| 笔尖肩部、笔夹末端只能用三点圆弧拼 | 草图没有样条，折线拐角不能倒圆 | 草图点加 `{ spline }` 和 `{ to, r }` |
| 整支笔只能建成一个实体 | 只支持「先建整体，再切开」 | 单文件新建零件；多个零件文件组成装配 |

## 已确认（2026-11-07）

- 写成一份大文档，四块这一轮全部做完，顺序是：观测与诊断 → 多零件与装配 → 建模能力 → 提示词收尾。
- 第一轮的 15 条全部按建议：
  1. 多零件两条路都做：先做单文件多零件，再做多文件装配。
  2. 装配文件 `*.arbor-asm.json` 只放参数、零件清单和核对表，不放几何特征。
  3. 零件只用平移和旋转来摆（可以写参数表达式），不做约束求解和运动。「贴合摆放」以后再做。
  4. 零件之间共用尺寸靠共享参数文件；同名参数以共享文件为准。
  5. 一期不做跨文件的几何引用。
  6. 在装配里改零件：其他零件半透明地显示在原位，只读，可以量、可以核对。
  7. 多文件装配只在桌面版有。
  8. 新能力的范围按上面的「范围」；网页助教的工具说明和提示词不加，等网页评测通过后再放。
  9. 诊断只提示，不拦截。
  10. 最后一步改动的范围小于整件对角线的 10% 时，`look` 自动加一张特写。
  11. 验收用真实 agent 跑三道题。
- 第二轮的细节（装配文件的字段、爆炸、BOM、缓存失效）由实现方决定，写在下面各节里。

## 一、观测与诊断

### `look`

| 字段 | 写法 | 效果 |
| --- | --- | --- |
| `focus` | 特征 id，或 `{ "part": "笔尖" }`，或 `{ "faces": 面选择器 }` | 取景框只框住这些面（特征 id = 这一步生成和修改的、现在仍存在的面）。标签写「特写：笔尖修形」 |
| `section` | `{ "plane": "XY" \| "XZ" \| "YZ", "offset"?: 数值 }` | 用这个基准面剖开，去掉法向一侧（XY 去掉上面，XZ 去掉 -Y 那一侧，YZ 去掉 +X 那一侧），截面填色。没写 `views` 时出两张：正对截面的一张，加一张等轴测 |
| `dir` | `[x, y, z]` | 多一张从这个方向看的图，标签「从 (x, y, z) 方向看」 |
| `size` | `"large"` | 图片 896×672（缺省 448×336） |
| `hide` | 零件名的数组 | 不画这些零件（例如藏起笔帽看里面） |

- **自动特写**：没写 `focus` 时，算出显示那一步新生成的面的包围盒（不算被修改的面：小孔、小凸台也会改到它所在的大面，算上就框住整件了）。它的对角线小于整件对角线的 10% 时，在请求的视图后面加一张等轴测特写，标签「特写：〈特征名〉（自动）」。
- **比例尺**：结果文字写出整件尺寸和每张图的分辨率，例如「整件 147.5×15.1×12.6 mm；等轴测 1 px ≈ 0.39 mm；特写：笔尖修形 1 px ≈ 0.03 mm」。按取景球的直径和图宽估算。
- **实现位置**：都在画图这一侧（`renderViews`）。`focus` 用 `DisplayData.groups` 的 `origin`、`part`、`hash` 找到三角形算包围盒，再交给 `Snapshotter.draw({ box })`。`focus.faces` 先由引擎用 `locate` 换成 hash。剖视用 three.js 的裁剪平面加截面填色，和视口的剖视同一套（`section.ts`）。

### 每步的诊断（结果里的 ⚠，不拦截）

- **没接上**：加料特征（拉伸、旋转、扫掠、放样、筋，以及加料的阵列和镜像）前面已经有实体，而且这一步不是在新建零件时：工具体和已有实体的重叠体积为 0，最短距离又大于 0.001 mm，就报「⚠ 新加的料离已有实体 0.52 mm，没接上：会多出一块不相连的实体」。
- **只碰到边或点**：重叠体积为 0、距离为 0，但合并后实体变多了，就报「⚠ 新加的料只碰到已有实体的边或点，没有共用的面：合并后还是两块」。只是面贴面接触的，合并后是一块，不报。
- **极小碎面**：这一步新生成的面里，面积小于 0.01 mm² 的，报「⚠ 生成了 3 个极小的面（最小 0.002 mm²）：多半是两个面几乎重合，或者切除擦着面切过去」。
- **新零件和别的零件重叠**：加料新建零件时，如果和已有零件相交，报「⚠ 新零件「笔尖」和「握位」重叠 12.4 mm³」。装配也报（`component`）。

### `measure`

- 量的对象除了 `face`、`edge`，再加 `feature`（这个特征生成和修改的、现在仍存在的所有面）和 `part`（一个零件、一个参考体，或者在装配里改零件时上下文里的一个零件，按名字或 id）。
- 单个面或边的结果多给坐标：平面写「中心」和法向；圆柱面、圆弧边写「圆心」或轴线上的一点和轴向；直线边写两个端点。
- 两个对象里有 `feature` 或 `part` 时，给出「最短距离」，等于 0 就写「接触」。两边都是实体（`part`）时，再给「重叠体积」。

### 核对表（`check`）新增两项

| kind | 字段 | 怎么算 |
| --- | --- | --- |
| `position` | `at`（`face` 或 `edge`，选中一个）；`axis`（`X`/`Y`/`Z`，可选）；`expect`（写了 `axis` 时是一个数，没写时是 `[x, y, z]`） | 平面取中心，圆柱面、圆弧边取圆心（轴线上离面中心最近的点），直线边取中点 |
| `gap` | `a`、`b`：各是 `{ face }`、`{ edge }`、`{ feature }`、`{ part }` 之一；`min`、`max`：可选，至少写一个 | 最短距离 d。`max: 0` 就是要求接触；两边都是实体且相交时，d 记为 0，同时报出重叠体积；写了 `min > 0` 时，相交就算不过 |

- `clearance`、`interference` 原来的 `ref` 只能写 `import` 的 id，现在也可以写零件名（拆件、新建的零件，装配里的零件，在装配里改零件时上下文里的零件）。写的是零件名时，「另一边」是除了它以外的整个模型。
- 网页助教的 `check` 不出现这两项新的 kind（见「网页」）。

## 二、多零件与装配

### 什么时候用哪一种（写进提示词）

| 情况 | 用什么 |
| --- | --- |
| 一个实体切开（外壳的底壳和上盖、超长的杆分段打印） | 单文件 + `split` |
| 最多 3 件紧密配合、共用很多尺寸的零件（笔尖和笔舌、盒子和盖板） | 单文件 + 加料时写新零件名 |
| 要复用的零件、标准件、外购件（STEP）、超过 3 件，或者体积大、要分开维护 | 多文件装配 |

### 单文件里新建零件

- 加料特征写 `part`，而这个名字还不存在时，就新建一个零件，这一步的工具体就是它的形状，不和别的零件合并（两块重叠时给 ⚠，见上）。
- 这时还没有实体：这个名字就是第一个零件的名字。
- 已经有一个没名字的实体：它被叫作「主体」，结果里写明「原来的实体叫作「主体」」。
- 后面的特征写 `part: "笔尖"` 就只改它，规则和拆件之后相同（切除和孔不写 `part` 时作用在碰到的所有零件上，等等）。
- 阵列、镜像复制一个新建零件的特征时，复制出来的料并到同一个零件里。
- 爆炸：新建的零件没有切面。其中体积最大的一个不动（和拆件时下面的零件不动一样），其余的从它的中心指向自己的中心移开，距离和拆件一样，是整体沿这个方向尺寸的 0.6 倍，至少 15 mm。拆件拆出来的零件照旧按切面的法向移动。
- 能用的特征：`extrude`、`revolve`、`sweep`、`loft`、`import`（`mode: add`）。

### 共享参数文件

- 文件 `*.params.json`：`{ "params": { "D": 11 }, "paramNotes": { "D": "笔杆直径" } }`。
- 特征树加字段 `uses`：共享参数文件的路径，相对零件文件所在的文件夹。零件和装配都可以写。
- **合并**：引擎在交给内核之前合并，内核看不到 `uses`。规则是 `{ ...自己的参数, ...共享参数 }`，同名时以共享的为准，并给出「⚠ 参数 D 在共享参数文件里也有，以共享的为准」。自己的参数可以引用共享参数。
- **改**：`set_params` 改到共享文件里已有的名字时，写回共享文件，结果写「共享参数（pen.params.json），用到它的零件会一起变」。要新建共享参数，写 `shared: true`。窗口的参数面板里，共享参数带一个「共享」标签，改它同样写回共享文件。
- **跟着变**：引擎监视共享文件。它一改，所有打开着、用到它的零件和装配都重建，「动态」里记一笔「文件」的改动。
- **出错**：文件不存在或格式不对时，报参数错误：「共享参数文件 pen.params.json 读不到：…」。
- **写入**：每次写共享文件前，先重读磁盘上的最新内容，只把这次的增删合并上去；合并后共享文件自己要能算出来（不能引用某个零件自己的参数），算不出来就不写，报「共享参数不对，没有写入」。
- **遮蔽**：零件自己有、共享文件里也有的同名参数被遮住时，零件文件里保留它自己的值和说明，别的编辑不会改它。停用共享文件时，留下的是正在用的共享值。
- **网页**：网页读不到文件。特征树带 `uses` 时，网页照常重建，缺的参数按参数错误报出来。

### 装配文件 `*.arbor-asm.json`

装配文件就是特征树格式（`params`、`paramNotes`、`uses`、`features`、`checks`），只是特征都是 `component`。这样参数、撤销、监视文件、备注、核对、测量、爆炸、分件导出都直接用现成的。

```json
{ "uses": "pen.params.json",
  "params": {},
  "features": [
    { "id": "body", "op": "component", "name": "笔杆", "file": "barrel.arbor.json" },
    { "id": "cap", "op": "component", "name": "笔帽", "file": "cap.arbor.json", "at": [0, 0, "-Lcap+Lpost"] },
    { "id": "nib", "op": "component", "name": "笔尖", "file": "nib.arbor.json", "at": [0, 0, "zf"] },
    { "id": "screw", "op": "component", "name": "螺钉", "file": "vendor/m2x4.step", "rotate": [{ "axis": "X", "angle": 90 }], "at": [5, 0, 10] }
  ],
  "checks": [{ "id": "seat", "kind": "gap", "said": "笔尖压在笔舌上", "a": { "part": "笔尖" }, "b": { "part": "笔舌" }, "max": 0 }] }
```

| 问题 | 决定 | 理由 |
| --- | --- | --- |
| `component` 的字段 | `name`（零件名，缺省用文件名）、`file`（`.arbor.json`、`.arbor-asm.json` 或 `.step`/`.stp`）、`rotate`（同 `import`：依次绕过原点的坐标轴转，先转后移）、`at`、`hidden` | 摆放写法和 `import` 一样，agent 已经会写 |
| 装配里能放什么 | 只能放 `component`。混进别的特征时，那一步报错：「装配里只能放零件（component）。要改零件的形状，用 open_part 打开它的文件」 | 装配里打的孔不属于任何零件文件，导出的零件就和看到的不一样 |
| 零件文件里放 `component` | 报错：「零件文件里不能放 component；新建一个 .arbor-asm.json 装配文件」 | 两种文件各管各的 |
| 子装配 | `file` 可以是另一个 `.arbor-asm.json`，最多套 4 层，循环引用报错 | 大件按部件分组 |
| 零件文件本身有多个零件（拆过件） | 每个零件都进装配，名字写成「组件名/零件名」 | 拆好的外壳整个拿进来 |
| 零件文件有失败的特征 | 用它最后一个成功的步骤的形状，并报「⚠ 零件「笔尖」有 1 个特征失败，用的是失败前的形状」；一步都没成功就报错 | 一个零件坏了，整个装配还能看 |
| 文件找不到、格式不对 | 这一步报错，写出路径和原因 | — |
| 颜色和爆炸 | 每个组件是一个零件，用零件色；爆炸从装配中心指向组件中心 | 现成的 |
| 面的来历 | 组件的所有面都记在这个 `component` 上，所以 `of: "nib"` 能选中笔尖的面；候选列表带零件名 | 现成的选择器就够用 |
| 核对、测量 | 用零件名：`gap`、`clearance`、`interference`、`measure` 的 `part`；`size`、`volume` 量整个装配 | — |
| 导出 | `step`：一个文件里多个带名字的零件，零件摆在装配位置；`stl`：一个零件时是单个文件，多个时打包成 zip，每个零件一个文件；`bom`：Markdown 表格，列出序号、名称、文件、数量（同一个文件用了几次）、单件体积、外形尺寸；`py`：报错「装配不能导出成 build123d 代码，请分别导出每个零件」；`json`：装配文件本身 | — |
| `inspect body`、`get_state` | 按零件列出名字、文件、体积、外形尺寸 | — |

### 内核里怎么同时拿到多个零件

- 内核线程只有一个 `Kernel`，引擎一次只让它装一个文件。装配需要所有零件的形状。
- 做法：
  1. 引擎把装配用到的文件都递归读出来，每个零件文件已经合好共享参数，`import` 的 STEP 字节也一起读好。
  2. 引擎用 `setComponents(list)` 交给内核，和 `setAssets` 是同一种做法。
  3. 内核里另起一个临时的 `Kernel` 建每个零件，只留下最后的形状（克隆），然后把这个临时 `Kernel` 释放掉。
  4. 建好的形状按「特征树 JSON + 共享参数 + STEP 内容哈希 + 子装配的键」缓存（模块级 LRU，16 份）。
- 结果：只改了笔尖时，只重建笔尖；切换回装配时，零件不用重建。
- 监视：引擎监视装配用到的每个文件（零件文件、共享参数文件、STEP）。任何一个变了，就重建打开着的装配，「动态」里记「文件」的改动。

### 在装配里改零件

- `open_part` 加 `context: "pen.arbor-asm.json"`。装配里必须有一个组件的 `file` 就是这个零件，否则报错。
- 打开以后：
  - 装配里的其他零件按相对位置，作为参考体半透明地显示在这个零件的坐标系里。
  - `look` 画出它们（`hide` 可以藏起来）；`measure` 的 `part`、核对表的 `gap`、`clearance`、`interference` 可以写它们的名字。
  - 它们只读，选择器选不到它们的面，和 `import` 参考体一样。
- 这个零件出现多次时，用第一个组件的位置，并给出提示。
- 上下文记在引擎的文档状态里，不写进零件文件。`open_part` 再打开同一个零件、不带 `context`，就退出上下文。
- 窗口：标题下面一行「在装配「钢笔」里编辑 · 其他零件半透明」，带「回到装配」按钮。在装配里，单击一个组件的特征卡片，卡片上有「在装配里编辑」按钮。

### 打开、列出

- `open_part` 接受 `.arbor-asm.json`，`create: true` 时新建一个空装配。
- `list_parts` 写出种类（零件 / 装配）。
- 窗口的「打开」对话框、最近打开的列表、拖进窗口都接受这种文件。

## 三、建模能力

| 能力 | 写法 | 说明 |
| --- | --- | --- |
| 求交 | `extrude`、`revolve`、`sweep`、`loft` 的 `mode: "intersect"` | 只留下工具体和实体重叠的部分。有多个零件时必须写 `part`。例：笔尖 = 半圆锥薄壳 ∩ 盾形轮廓拉伸 |
| 旋转起始角 | `revolve.start`（度） | 从草图所在的位置，绕轴按右手定则先转 `start` 再开始旋转 |
| 对称旋转 | `revolve.symmetric: true` | 以草图所在的位置为中线，两侧各转 `angle/2` |
| 草图样条 | 草图点里写 `{ "spline": [[x, y], …] }`（`polyline`、`path`、扫掠路径） | 从上一个点出发，光滑地依次经过这些点，最后一个点是终点 |
| 拐角圆角 | 草图点里写 `{ "to": [x, y], "r": 2 }` | 走到这个点，这个拐角倒 R2 圆角 |
| 沿面等深 | `extrude.onto`：一个面选择器，选中一个平面或圆柱面 | 草图沿法向投影到这个面上，切除时从面往里切 `distance` 深，加料时从面往外长 `distance` 高。圆柱面上的字各处等深。只支持平面和圆柱面，选中别的面时报错 |

- **实现**：
  - 求交：用 `Shape3D.intersect`。
  - 起始角：先建好旋转体，再绕轴转 `start`（对称时转 `-angle/2`）。
  - 样条：replicad 的 `smoothSplineTo`；拐角圆角：`customCorner`。
  - `onto`：先把草图拉伸成两侧都很长的柱体，再和「面的厚度带」求交，得到等深的工具体。厚度带在平面上是一块板，在圆柱面上是两个同轴圆柱之差。
- **build123d 导出**：
  - 求交写 `mode=Mode.INTERSECT`；
  - 起始角先 `revolve` 再 `.rotate`；
  - 样条用 `Spline`，拐角圆角用 `fillet` 2D；
  - `onto` 写出等价的求交；
  - `component` 不导出（见上）。

## 四、提示词与流程（`AGENT_GUIDE`）

- **第 0 步（新增）**：开建前先用一两句话说出四件事：要建的是什么（例如「钢笔：有钢制笔尖的自来水笔」）；零件清单；做到什么程度；用单文件还是装配。拿不准是什么东西、要不要某个部件，就先问用户。
- **验证（改写第 5 条）**：
  - 用 `look` 看。最后一步改动很小时，结果里会有一张自动特写。看不清的地方，用 `focus`、`section` 再看，不要说「请到窗口里放大看」就收尾。
  - 应该贴在一起的地方（笔尖压在笔舌上、盖子落在止口上），加一条 `gap`，写 `max: 0`。
  - 坐标要求用 `position`。
  - 别自己推算，用 `measure`。
- **零件规划（新增一节）**：上面那张「什么时候用哪一种」的表，加上装配文件、`component`、共享参数、`open_part` 的 `context` 的写法。
- **新能力（新增一节）**：求交、`start`、`symmetric`、`spline`、`r`、`onto` 各一行。
- **做不到的**：去掉「装配约束」以外已经能做的，写成「装配只能用平移和旋转摆放，没有约束和运动」。
- **网页**：网页的 `SYSTEM_PROMPT` 不变。

## 风险

- **内存**：装配时临时 `Kernel` 建零件会多占内存。每建完一个零件就释放它，只留最后的形状；缓存最多 16 份。引擎原来就有「wasm 堆超过 1.4 GB 换线程」的保护。
- **速度**：第一次打开装配要把所有零件建一遍。之后有缓存，只重建改过的零件。
- **诊断的误报**：「只碰到边」靠合并后实体的个数来判断，只在这一步让实体变多时才报。
- **网页工具的格式**：网页助教的工具描述要保持原样。单元测试检查网页工具的 JSON Schema 里没有新字段。
- **装配和零件互相引用**：循环引用报错，最多 4 层，防止无限递归。

## 实现中发现并处理的

- **共面的新面被算成「被修改」**（原有问题）：
  - 原来判断「被修改」时，只看新面上的一点是否落在旧面的曲面上。所以第二个和第一个一样高的凸台，顶面会被算成第一个凸台的，`of: "b2"` 选不全，按特征量距离也会量错。
  - 现在还要求新旧两个面的包围盒有重叠。拉伸、修剪、延伸出来的面都和原来的位置重叠，不受影响。
- **自动特写只看新生成的面**：小孔、小凸台也会修改它所在的大面，算上就框住整件了。
- **replicad 的 `makeCompound` 会释放传进去的形状**：用零件名核对间隙时，零件的实体被它释放了，后面再用就报 “This object has been deleted”。改用项目里不释放输入的 `compoundOf`。
- **新建零件的爆炸**：原先让所有零件都从整体中心散开。改成体积最大的不动、其余移开，和拆件时下面的零件不动一致。
- **`onto` 在圆柱面上会刻到背面**：草图沿法向一直投影过去，会穿过圆柱的两侧。现在只留草图正对的那一侧；草图平面过轴线时两侧都留，比如孔壁上的环槽。
- **装配里报零件的碎面**：组件的面属于它的零件文件，碎面已经在零件文件里报过一次，装配那一步不再重复。
- **`get_state` 的特征列表没有警告**：每一行现在带上这一步的 ⚠。
- **测试的内存磁盘不解析 `..`**：真实的文件系统会解析，零件在子文件夹里写 `uses: "../pen.params.json"` 时测试读不到。改成和真实文件系统一样解析。
- **BOM 体积**：小零件（笔尖 0.04 cm³）保留一位小数会显示成 0，改为两位。
- **开发环境**：
  - `desktop` 里 `npm install` 没有下载 Electron 的二进制文件，要用镜像再运行一次 `node node_modules/electron/install.js`。
  - 本机已经装了 Arbor 并在运行时，开发版用 `ARBOR_HOME=<别的目录>` 加 `--user-data-dir=<别的目录>` 另起一个窗口，就不会和已安装的那个抢单实例锁。
